Bitácora de Error #1	Every Click Has an Outcome

## Organización del Proyecto y Decisiones Iniciales

## 1. Contexto

Durante la Unidad 1 comenzamos la organización del proyecto “Every Click Has an Outcome”. En esta etapa inicial nos enfocamos en definir la base de datos a utilizar, establecer la pregunta de investigación, organizar el flujo de trabajo en GitHub y coordinar el trabajo en equipo. A continuación documentamos los problemas que se presentaron y las acciones que tomamos para resolverlos.

## 2. Problemas presentados y acciones tomadas

## 3. Ajustes de mejora aplicados

Realizar una reunión de lluvia de ideas antes de tomar decisiones clave, para centralizar el criterio del equipo.

Coordinar con anticipación los commits en GitHub para evitar que se sobrescriban o se desordenen los cambios.

Definir un día fijo de reunión semanal que se ajuste a la disponibilidad de ambos integrantes.

Adelantar tareas siguientes cuando una etapa se complete antes de lo previsto, para compensar los retrasos de otras etapas.

## 4. Conclusiones

Los problemas presentados en esta primera etapa fueron principalmente de organización y coordinación del equipo, más que de contenido técnico. Identificar estos inconvenientes a tiempo nos permitió ajustar la forma de trabajar en equipo, mejorar el uso de GitHub y establecer una dinámica de reuniones más efectiva. Estas lecciones sirvieron de base para que las siguientes etapas del proyecto, incluida la auditoría de calidad de los datos, se desarrollaran con mayor orden y menos contratiempos.



| Problema | ¿Qué pasó? | Acción tomada |

|---|---|---|

| Decisión de la base de datos | Al inicio no logramos centralizar las ideas ni ponernos de acuerdo sobre qué base de datos usar ni qué pregunta de investigación queríamos responder. | Organizamos una reunión y una lluvia de ideas para evaluar opciones en conjunto y así elegir la base de datos y definir la pregunta del proyecto. |

| Conflictos de commits en GitHub | Durante el trabajo de calidad de los datos tuvimos problemas recurrentes al actualizar commits al mismo tiempo, lo que provocaba que los cambios se traspusieran en un orden equivocado. | Ajustamos la forma de sincronizar el repositorio para evitar subir cambios simultáneos y así reducir los conflictos de orden en los commits. |

| Coordinación de reuniones | Fue difícil cuadrar un día específico que le sirviera a todo el equipo y que además permitiera presentar avances significativos en cada sesión. | Buscamos un horario común revisando la disponibilidad de ambos integrantes para definir un día fijo de reunión. |

| Retrasos en el cronograma | La etapa de calidad de datos, programada para terminar el 4 de agosto, se extendió: en realidad comenzó el 6 y terminó el 8, ya que no se contaba con suficiente tiempo disponible. | Como la etapa de calidad no tomó tanto tiempo como se esperaba, adelantamos el inicio del preprocesamiento para compensar el retraso y mantener el avance general del proyecto. |
